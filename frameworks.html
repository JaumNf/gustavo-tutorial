Outras formas de construir

O que você não usa hoje — e por isso mesmo vale entender. Aqui o objetivo não é trocar de ferramenta: é enxergar o mesmo problema resolvido de três jeitos e saber julgar cada um.

O mesmo card em três abordagens

Novo

Um card de drink, com nome, ingredientes e um selo de “sem álcool”. Mesmo resultado visual, três caminhos.

1. HTML puro — o seu jeito

vanilla
<article class="card">
  <h3 class="card__nome">Pantanal</h3>
  <p class="card__ingredientes">maracujá · hortelã · tônica</p>
  <span class="card__selo">sem álcool</span>
</article>

<style>
  .card { padding: 20px; border: 1px solid #ddd; border-radius: 6px; }
  .card__nome { font-size: 20px; margin: 0 0 6px; }
  .card__selo { font-size: 11px; text-transform: uppercase; color: #7A1C30; }
</style>

Para dez drinks, você repete o bloco dez vezes — ou gera com map() a partir de um array, como vimos na Parte 5.

2. React — componente com propriedades

react
function Card({ nome, ingredientes, semAlcool }) {
  return (
    <article className="card">
      <h3 className="card__nome">{nome}</h3>
      <p className="card__ingredientes">{ingredientes.join(' · ')}</p>
      {semAlcool && <span className="card__selo">sem álcool</span>}
    </article>
  );
}

// usando com uma lista
<div className="carta">
  {drinks.map(d => <Card key={d.nome} {...d} />)}
</div>

O card virou uma função que recebe dados. O {semAlcool && ...} é a forma do React de dizer “só mostre se for verdadeiro”. O key é obrigatório em listas — é como o React identifica cada item quando algo muda.

3. Tailwind — estilo direto na marcação

tailwind
<article class="p-5 border border-gray-300 rounded-md">
  <h3 class="text-xl mb-1.5">Pantanal</h3>
  <p class="text-gray-600">maracujá · hortelã · tônica</p>
  <span class="text-xs uppercase text-red-900">sem álcool</span>
</article>

Não existe arquivo de CSS: cada classe é uma propriedade. Rápido de escrever, e a marcação fica longa.

O que essa comparação deve deixar claro: nenhuma das três é melhor em abstrato. O React ganha quando existem muitos componentes com estado mudando; o Tailwind ganha quando várias pessoas mexem no mesmo projeto e ninguém quer brigar por nome de classe; o vanilla ganha quando o projeto é pequeno, precisa durar e não deve depender de nada.

Pensar em componentes

Novo

Esta é a ideia que vale levar de volta para o HTML puro, mesmo sem nunca usar framework. Componente é uma unidade fechada: aparência, comportamento e dados no mesmo lugar, sem depender de onde foi colocada.

nomeando como componente (BEM)
/* bloco */          .card { }
/* elemento */       .card__titulo { }
                     .card__selo { }
/* modificador */    .card--destaque { }
                     .card--sem-foto { }

Essa convenção — chamada BEM — resolve dois problemas de uma vez: o nome diz a que componente a regra pertence, e a especificidade fica sempre baixa e igual, então nada briga com nada.

Web Components — componentes de verdade, sem framework

O navegador permite criar suas próprias tags. Não é comum em landing page, mas é a resposta nativa ao problema que o React resolve.

javascript
class BotaoZap extends HTMLElement {
  connectedCallback() {
    const numero = this.getAttribute('numero');
    const texto  = this.getAttribute('texto') || 'Falar no WhatsApp';
    this.innerHTML =
      `<a class="botao" target="_blank" rel="noopener"
          href="https://wa.me/${numero}">${texto}</a>`;
  }
}
customElements.define('botao-zap', BotaoZap);
usando
<botao-zap numero="5567999999999" texto="Pedir orçamento"></botao-zap>
A lição transferível: mesmo sem Web Components, organize seu CSS por componente e não por página. Um bloco /* === CARD === */ com tudo sobre o card junto é a versão simples dessa ideia — e é o que torna o copiar-e-colar entre projetos confiável.

Começando um projeto com Vite

Novo

Se um dia você quiser experimentar React ou trabalhar com arquivos separados e build, o caminho de entrada hoje é o Vite. Vale fazer uma vez só para ver como é.

terminal
npm create vite@latest meu-projeto
# escolha "Vanilla" para JS puro, ou "React"

cd meu-projeto
npm install
npm run dev      # servidor local, recarrega ao salvar
npm run build    # gera a pasta dist/ pronta para publicar
Pasta / arquivoO que é
index.htmlA página. Aqui ele fica na raiz, não escondido
src/Seu código-fonte
public/Arquivos copiados sem processamento (favicon, imagens)
dist/O resultado do build — é isso que vai pro servidor
node_modules/Dependências baixadas. Nunca vai pro Git
O que muda no seu dia: você deixa de abrir o arquivo e passa a rodar um comando. Em troca ganha recarga automática, imports entre arquivos e minificação no build. Para landing page única, é troca ruim; para um projeto com muitas telas, é troca óbvia.

Tailwind na prática

Novo CSS

Vale entender porque é o que você mais vai encontrar em vaga, tutorial e projeto de terceiro. A ideia: em vez de nomear componentes, você compõe a partir de classes de uma propriedade cada.

a lógica das classes
p-4          padding: 1rem
px-6         padding esquerda e direita: 1.5rem
mt-2         margin-top: 0.5rem
text-xl      font-size: 1.25rem
font-bold    font-weight: 700
flex         display: flex
gap-4        gap: 1rem
md:flex-row  vira linha a partir do breakpoint médio
hover:bg-red-900   muda o fundo no hover

Os prefixos são a parte inteligente: md:, hover:, dark:, focus: aplicam a classe só naquela condição — sem escrever media query nem pseudo-classe.

Ganha emPerde em
Velocidade de escritaHTML fica longo e difícil de ler
Nunca inventar nome de classeMudar todos os botões exige editar cada um
Consistência forçada por uma escalaExige build para funcionar bem
CSS final pequeno (remove o não usado)Curva até decorar as abreviações
Não use a versão CDN em produção. Ela compila no navegador do visitante, o que é lento e pesado. A CDN serve para testar e aprender; num projeto real, Tailwind precisa do build que remove as classes não usadas.
O que dá para roubar sem adotar: a escala de espaçamento. Tailwind usa múltiplos de 4px, e obrigar-se a isso — 4, 8, 12, 16, 24, 32, 48 — elimina aquele espaçamento de 13px que só existe porque ficou parecendo certo na hora. Dá para fazer isso com variáveis CSS no seu arquivo único.
