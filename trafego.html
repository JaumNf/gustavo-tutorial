Tráfego e visibilidade

A pergunta que todo cliente faz depois de quanto custa: vai aparecer no Google? Esta trilha responde de verdade — incluindo a parte que quase nenhum desenvolvedor conta, que é o perfil no Google valer mais que o site para negócio local.

Mostrar

Nenhum tópico com esse filtro.

PARTE 1

Como a busca funciona

Antes de otimizar qualquer coisa, entender o mecanismo. Três etapas, e a maioria dos problemas de "não aparece no Google" acontece na primeira.

Rastrear, indexar, ranquear

Novo

Buscador não pesquisa a internet quando você digita. Ele consulta um índice que montou antes. São três etapas distintas, e confundi-las leva a diagnóstico errado.

as três etapas
1. RASTREAR   um robô visita a página e lê o HTML
              falha se: bloqueado por robots.txt, servidor fora,
              conteúdo só aparece depois de JavaScript

2. INDEXAR    a página é analisada e guardada no índice
              falha se: conteúdo duplicado, sem valor, noindex,
              página órfã sem nenhum link apontando

3. RANQUEAR   o índice é ordenado para cada busca
              aqui entram relevância, autoridade, experiência
              de uso e intenção da busca

"O site não aparece no Google" quase nunca é problema de ranqueamento no começo — é de rastreamento ou indexação. Site novo simplesmente ainda não foi visitado, ou foi visitado e não entrou no índice.

Como verificar em dez segundos: busque site:seudominio.com.br no Google. Se aparecer resultado, a página está indexada e o problema é de posição. Se não aparecer nada, o problema é anterior — e otimizar título não resolve.

robots.txt e sitemap.xml

NovoHTML

Dois arquivos de texto na raiz do site que conversam com o robô. Para uma landing page simples eles quase não importam; a partir de várias páginas, passam a importar.

robots.txt
# permite tudo e aponta o mapa do site
User-agent: *
Allow: /

Sitemap: https://seudominio.com.br/sitemap.xml
sitemap.xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://seudominio.com.br/</loc>
    <lastmod>2026-09-18</lastmod>
  </url>
  <url>
    <loc>https://seudominio.com.br/servicos.html</loc>
    <lastmod>2026-09-18</lastmod>
  </url>
</urlset>
O erro que mata site inteiro: subir para produção com Disallow: / no robots.txt, ou com <meta name="robots" content="noindex"> que ficou do ambiente de teste. O site funciona perfeitamente, e simplesmente nunca aparece. Vale conferir isso no checklist de lançamento.

Outro detalhe: o canonical. Se a mesma página abre em com.br, www.com.br e com.br/index.html, o buscador vê três páginas iguais. A tag <link rel="canonical"> diz qual é a oficial.

Por que HTML puro tem vantagem aqui

Novo

O robô lê o HTML que chega do servidor. Se o conteúdo só existe depois que o JavaScript roda, ele depende de uma segunda passada de processamento — que acontece, mas demora mais e falha mais.

Numa página feita em HTML puro, todo o conteúdo já está no arquivo. Não existe essa etapa extra, não existe risco. É uma vantagem real da sua forma de entregar, e vale dizer isso ao cliente.

Onde você pode se prejudicar sozinho: se um acordeão, um carrossel ou um bloco com opacity: 0 esperando o IntersectionObserver esconder conteúdo que só aparece via JS, esse conteúdo pode não contar. O <details> nativo, ao contrário, mantém o texto no HTML mesmo fechado — mais um motivo para preferi-lo.
PARTE 2

Search Console

A ferramenta mais útil e mais ignorada do conjunto. É gratuita, é do Google, e mostra exatamente o que ele pensa do site do seu cliente.

O que ele responde

Novo

Analytics mostra o que acontece dentro do site. Search Console mostra o que acontece antes — na busca, onde a decisão de clicar é tomada. Para SEO, é a fonte primária.

RelatórioResponde
DesempenhoQue buscas mostram o site, quantas impressões, quantos cliques, em que posição
Indexação de páginasO que está no índice e o que ficou de fora — com o motivo
Inspeção de URLO estado de uma página específica, e o botão para pedir indexação
Core Web VitalsVelocidade e estabilidade medidas em visitantes reais, não em teste
Usabilidade em dispositivos móveisProblemas de leitura e toque no celular

A verificação de propriedade é feita por uma tag no <head> ou por registro DNS. Como você controla o HTML, a tag é o caminho de dois minutos.

O que fazer com os dados

Novo

O relatório de desempenho vira ação quando você cruza impressão com clique.

PadrãoDiagnósticoO que fazer
Muita impressão, pouco cliqueAparece, mas o resultado não convenceReescrever title e description daquela busca
Posição 8 a 15 em busca relevantePerto da primeira páginaReforçar o conteúdo sobre esse tema — é o ganho mais fácil
Buscas que você não esperavaO público usa outras palavrasAdotar as palavras dele na página

O caso mais comum e mais fácil de resolver: a página aparece bem para uma busca, mas com um título que não responde àquela busca. Trocar o <title> é uma linha de código e costuma ser a mudança de maior retorno em SEO de site pequeno.
PARTE 3

SEO na prática

O que realmente move ponteiro num site pequeno, e o que é mito repetido.

Intenção de busca

Novo

O conceito mais útil de SEO, e o mais ignorado. Duas buscas com as mesmas palavras podem querer coisas opostas, e a página precisa corresponder ao que a pessoa quer naquele momento.

IntençãoExemplo de buscaA página certa
Informacional"quanto custa reformar um apartamento"Conteúdo que explica, não página de venda
Comercial"melhor arquiteta campo grande"Comparação, prova, portfólio
Transacional"arquiteta campo grande orçamento"A landing page, com CTA visível
Navegacional"vanessa carvalho arquitetura"A home. Já sabe quem procura

A consequência prática: uma landing page de venda dificilmente ranqueia para busca informacional, e forçar isso não funciona. Se o cliente quer aparecer para "quanto custa reformar", o caminho é conteúdo — um artigo que responda —, não otimizar a LP.

Escolher palavras para negócio local

Novo

Negócio local não compete por termo genérico, e não deveria tentar. "Arquiteta" tem volume nacional e concorrência impossível; "arquiteta de interiores em Campo Grande" tem volume pequeno e intenção altíssima.

Como levantar sem ferramenta paga

  • O autocompletar do Google. Digite o serviço e a cidade e veja o que ele sugere — são buscas reais.
  • "Pessoas também perguntam". Caixa de perguntas no meio dos resultados. Cada uma é uma dúvida real do público.
  • Buscas relacionadas, no rodapé da página de resultados.
  • O Search Console do próprio cliente, depois de um mês no ar. É a fonte mais confiável, porque são as buscas que já trazem gente.
  • O WhatsApp do cliente. As palavras que as pessoas usam ao perguntar são as mesmas que usam ao buscar.
Regra prática: uma página, um tema principal. Tentar ranquear a mesma página para "reforma", "decoração", "projeto" e "marcenaria" costuma resultar em não ranquear para nenhum. Se são quatro serviços distintos, são quatro páginas.

Dois mitos que ainda circulam: repetir a palavra-chave várias vezes no texto ("keyword stuffing") hoje atrapalha em vez de ajudar; e a meta keywords não é usada por nenhum buscador relevante há mais de uma década.

Por que uma LP sozinha ranqueia pouco

Novo

Vale ser honesto com o cliente sobre isso, de preferência antes de fechar. Uma landing page única é excelente para converter quem já chegou, e fraca para trazer gente pela busca orgânica — ela responde a uma intenção só, tem pouco conteúdo e poucos motivos para outros sites a linkarem.

Os caminhos para trazer tráfego, em ordem de esforço:

  1. Perfil da Empresa no Google. Para negócio local, quase sempre traz mais contato que o site. É a Parte 4.
  2. Páginas por serviço. Uma para cada serviço principal, cada uma respondendo a uma busca diferente.
  3. Conteúdo que responde dúvida. Um punhado de artigos bons sobre as perguntas reais do público.
  4. Anúncio. Traz tráfego imediato enquanto o orgânico não existe — e custa dinheiro todo mês.
Como isso vira proposta: "a landing page converte quem chega; para chegar gente, existem três caminhos". Isso posiciona você como quem entende o problema inteiro — e abre trabalho recorrente em vez de projeto único.
PARTE 4

SEO local

Para cliente de serviço local, esta parte vale mais que todo o resto da trilha junta — e quase nenhum desenvolvedor fala sobre ela.

O Perfil da Empresa no Google

Novo

Quando alguém busca um serviço com intenção local, o bloco de mapa com três empresas aparece acima dos resultados normais. Esse bloco vem do Perfil da Empresa — o antigo Google Meu Negócio — e não do site.

Ou seja: é possível um cliente receber contato todo dia sem ter site nenhum, e é possível ter um site lindo e não aparecer ali. Para negócio local, o perfil costuma ser o ativo mais importante.

O que faz diferença no perfil

  • Categoria principal correta. A escolha da categoria é provavelmente a decisão mais determinante, e muita gente escolhe errado.
  • Endereço e área de atendimento coerentes com onde ele realmente atende.
  • Avaliações — quantidade, nota e, principalmente, constância. Vinte avaliações ao longo do ano valem mais que vinte no mesmo dia.
  • Respostas às avaliações, inclusive às negativas. Mostra que o negócio está vivo.
  • Fotos reais e recentes, adicionadas com frequência.
  • Horário correto, incluindo feriados.
  • Serviços e descrição preenchidos com as palavras que o público usa.
O que isso significa para você: configurar e organizar o perfil do cliente é um serviço vendável, leva uma tarde, e costuma dar mais resultado que qualquer ajuste no site. É também a melhor porta de entrada para um plano mensal.

Consistência de nome, endereço e telefone

Novo

O buscador cruza informações de várias fontes para confiar que um negócio existe e é aquele mesmo. Se o telefone no site é diferente do perfil, e o endereço aparece escrito de três jeitos em diretórios diferentes, essa confiança cai.

A sigla que se usa é NAP — nome, endereço, telefone. A regra é simples: exatamente igual em todo lugar, até na abreviação da rua.

o mesmo dado, marcado no site
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "name": "Vanessa Carvalho Arquitetura",
  "telephone": "+556799999-9999",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "Rua Exemplo, 123",
    "addressLocality": "Campo Grande",
    "addressRegion": "MS",
    "postalCode": "79000-000"
  },
  "areaServed": "Campo Grande e região",
  "url": "https://vanessacarvalho.com.br"
}
</script>

Esse bloco no site, batendo exatamente com o perfil, é o sinal mais direto que você pode dar — e é HTML puro, sem dependência nenhuma.

Avaliações: como pedir sem constranger

Novo

Avaliação é o item que mais move o perfil e o que mais gera desconforto em pedir. Três coisas resolvem quase tudo.

Pedir na hora certa. O melhor momento é logo depois da entrega, quando o cliente está satisfeito — não semanas depois.

Pedir com um link direto. O Google gera um link curto de avaliação. Mandar "clique aqui e deixe sua avaliação" converte muito mais que "procura a gente no Google e avalia".

Tornar rotina. Uma mensagem padrão enviada a todo cliente ao finalizar. Não depende de lembrar nem de coragem.

O que não fazer: comprar avaliação, pedir para amigos que não foram clientes, ou oferecer desconto em troca. Além de violar as regras da plataforma e arriscar o perfil, avaliação falsa é reconhecível — e o dano de ser pego é maior que o ganho.

Sobre avaliação negativa: responder com calma e oferecer solução costuma impressionar mais quem lê do que uma sequência de notas cinco. Quem está decidindo lê justamente as negativas para ver como o negócio reage.

PARTE 5

Analytics

Medir o que acontece dentro do site — e resistir à tentação de medir tudo.

GA4 na prática

NovoJS

O Google Analytics 4 funciona por eventos: tudo é um evento, inclusive visualizar uma página. Isso confunde quem vem da versão antiga, mas simplifica o que interessa — marcar a conversão.

a tag, no head
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){ dataLayer.push(arguments); }
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXX');
</script>
o evento que importa
// marca todo clique que leva ao WhatsApp, e de onde saiu
document.querySelectorAll('[href*="wa.me"]').forEach(function (link) {
  link.addEventListener('click', function () {
    if (typeof gtag !== 'function') return;
    gtag('event', 'clique_whatsapp', {
      origem: link.dataset.origem || 'sem-origem'
    });
  });
});

Com data-origem="hero", data-origem="flutuante" e data-origem="conversao" nos links, você descobre qual parte da página converte — informação que muda a próxima versão da página.

No painel do GA4, esse evento precisa ser marcado como evento principal (antiga "conversão") para aparecer nos relatórios certos. Sem esse passo, ele fica perdido no meio dos outros.

O que olhar e o que ignorar

Novo
OlheIgnore
Eventos de conversãoTempo médio na página
Origem do tráfegoTaxa de rejeição, isolada
Celular vs desktopMapa de calor sem volume
Páginas mais vistasVisitas totais como métrica de sucesso
Buscas do Search ConsoleQualquer número com menos de algumas dezenas de casos

A coluna da direita não é inútil — é ruidosa em volume pequeno. Com trinta visitas por semana, "tempo médio" é definido por duas pessoas que deixaram a aba aberta.

Alternativas mais leves: Plausible e Umami fazem o essencial, carregam bem menos, não usam cookie e simplificam a conversa de LGPD. Para landing page de cliente pequeno, costumam ser escolha melhor que o GA4 — que existe principalmente para integrar com anúncios.

Consentimento e LGPD

Novo

Analytics com cookie e pixel de anúncio coletam dado pessoal. Isso exige aviso claro e base legal, e a responsabilidade formal é do cliente — mas quem instalou a tag foi você.

O caminho limpo

  • Não instalar rastreamento que o cliente não pediu e não entende.
  • Se instalar, deixar aviso de cookies que realmente bloqueia antes do aceite — banner decorativo que carrega tudo assim mesmo é pior que nada, porque cria aparência de conformidade.
  • Ter política de privacidade acessível, ainda que simples.
  • Preferir ferramenta sem cookie quando a necessidade é só saber quantas visitas chegaram.
Isto é orientação prática, não parecer jurídico. Para caso concreto — principalmente em saúde, jurídico ou qualquer setor que trate dado sensível — a palavra final é de advogado.
PARTE 6

Anúncios, o básico

Você não precisa gerenciar campanha, mas precisa saber conversar sobre isso — porque a página que você entrega vai receber esse tráfego.

Busca ou rede social

Novo
Google Ads (busca)Meta Ads (Instagram e Facebook)
Estado da pessoaJá está procurandoNão estava procurando nada
TemperaturaMorno a quenteFrio
Página idealDireta, com CTA visível logoMais longa, começando pelo problema
Custo por cliqueMaiorMenor
Bom paraServiço com demanda existenteServiço que precisa ser despertado

Essa distinção é o que liga anúncio e página. Usar a mesma LP nos dois canais é o erro mais comum — e o motivo mais frequente de "investi em anúncio e não veio nada".

A regra da correspondência: a promessa do anúncio precisa aparecer na primeira tela da página, com as mesmas palavras. Se o anúncio diz "reforma com cronograma fechado" e a página abre com "transformamos ambientes", a pessoa sente que caiu no lugar errado e volta.

O que o cliente precisa entender

Novo

Três coisas evitam frustração e cobrança injusta em cima de você.

Anúncio é aluguel, não compra. No dia que parar de pagar, o tráfego some. Diferente do orgânico e do perfil no Google, que continuam trabalhando.

Precisa de volume mínimo para funcionar. Campanha com verba muito baixa não consegue aprender nem gerar dado suficiente para otimizar.

O gargalo raramente é a página. Se o anúncio traz público errado, nenhuma página converte. Separar as métricas — quantos cliques, quantas conversas, quantos fechamentos — mostra onde está o problema.

Sobre o pixel: se o cliente vai anunciar, o pixel precisa estar instalado antes do início da campanha, e o evento de conversão precisa disparar no clique do WhatsApp. Sem isso, a plataforma não tem como otimizar, e o dinheiro é gasto às cegas. É item de checklist de lançamento, não de depois.
PARTE 7

O sistema de visibilidade

Juntando tudo: o que fazer, em que ordem, nos primeiros noventa dias de um cliente novo.

Por que isso é bom comercialmente: esse roteiro transforma "fiz um site" em acompanhamento de três meses com entregas visíveis. É o argumento mais natural para mensalidade — e cada item da lista é pequeno, então o custo do seu lado é baixo.

Alinhar expectativa antes de prometer

Novo

SEO orgânico é lento. Perfil no Google é mais rápido. Anúncio é imediato e pago. Dizer isso na proposta evita a conversa ruim no mês seguinte.

E uma honestidade que protege você: ninguém garante primeira posição. Quem garante está vendendo o que não controla. O que se garante é o trabalho — site indexável, perfil bem configurado, conteúdo correspondente à busca, medição instalada — e isso é bastante.

Frase que funciona na proposta: "não vendo posição no Google, porque ninguém controla isso. Entrego o site pronto para ser encontrado, o perfil configurado e a medição funcionando — e a gente acompanha o resultado real por três meses."
PARTE 8

Fechar o ciclo: de onde veio o contato

A pergunta que todo cliente faz e quase nenhum fornecedor responde: "de onde vieram esses orçamentos?". Saber que o site teve 400 visitas não serve para decisão nenhuma. Saber que os seis contatos vieram do anúncio de reforma, e nenhum do de interiores, muda para onde o dinheiro dele vai no mês seguinte.

Por que o ciclo fica aberto

Novo

O caminho de um cliente local costuma ser este: vê um anúncio no Instagram, entra no site, clica no botão do WhatsApp, conversa, fecha. O problema é que o rastro se quebra em dois pontos.

EtapaQuem enxergaOnde quebra
Viu o anúncioGerenciador de anúncios—
Entrou no siteGA4Sem UTM, a origem vira "direto" ou "social" genérico
Clicou no WhatsAppNinguém, por padrãoPrimeira quebra: saída do site não é medida sozinha
Conversou e fechouSó o cliente sabeSegunda quebra: a conversa é do WhatsApp, não do site

As duas quebras têm conserto, e nenhum deles é caro. A primeira se resolve com evento de clique. A segunda, com a mensagem pré-preenchida carregando a origem.

UTM — marcar o link antes de soltar

Novo

UTM são parâmetros na URL que dizem ao Analytics de onde a pessoa veio. Sem eles, o GA4 chuta — e chuta mal, porque clique vindo de aplicativo costuma chegar sem referência nenhuma.

url
https://site.com.br/
  ?utm_source=instagram      ← ONDE estava o link (instagram, google, whatsapp)
  &utm_medium=cpc            ← COMO chegou (cpc, organic, social, bio, email)
  &utm_campaign=reforma-out  ← QUAL campanha
  &utm_content=video-cozinha ← QUAL criativo, quando há mais de um
Onde o link apareceMarcação sugerida
Bio do Instagramutm_source=instagram&utm_medium=bio
Anúncio no Metautm_source=instagram&utm_medium=cpc&utm_campaign=...
Google AdsAtive a marcação automática e não use UTM manual junto
Perfil da Empresa no Googleutm_source=google&utm_medium=perfil
Cartão com QR Codeutm_source=cartao&utm_medium=qr
Assinatura de e-mailutm_source=email&utm_medium=assinatura
Três regras que evitam relatório inútil: tudo em minúsculas e sem acento, porque Instagram e instagram viram duas linhas diferentes no relatório; nunca ponha UTM em link interno do próprio site, porque isso reinicia a sessão e apaga a origem verdadeira; e mantenha uma planilha com os nomes que você usa — três meses depois ninguém lembra se era reforma-out ou out-reforma.

Medir o clique no WhatsApp

NovoJS

Clique que leva para fora não é registrado sozinho. Como é justamente a conversão da página, ele precisa virar evento explícito.

js
document.querySelectorAll('a[href*="wa.me"]').forEach(function (a) {
  a.addEventListener('click', function () {
    if (typeof gtag !== 'function') return;
    gtag('event', 'clique_whatsapp', {
      origem_secao: a.closest('section')?.id || 'desconhecida',  // qual seção converteu
      texto_botao: a.textContent.trim().slice(0, 40)
    });
  });
});

No GA4, marque clique_whatsapp como evento principal (Admin → Eventos). A partir daí ele aparece nos relatórios como conversão, e a coluna de origem passa a mostrar quantos vieram de cada UTM.

O origem_secao é o detalhe que vale mais do que parece: se 80% dos cliques saem do botão da hero e nenhum do botão que está depois das dúvidas, você descobriu que ninguém chega ao fim da página — e isso é uma decisão de layout, não de anúncio.

A origem dentro da própria mensagem

NovoJS

Este é o truque que fecha a segunda quebra, e quase ninguém usa: a mensagem que abre no WhatsApp já chega ao cliente contando de onde a pessoa veio.

js
const params = new URLSearchParams(location.search);
const campanha = params.get('utm_campaign') || params.get('utm_source') || 'site';

document.querySelectorAll('a[href*="wa.me"]').forEach(function (a) {
  const secao = a.closest('section')?.id || 'geral';
  const texto = `Olá! Vim pelo site e quero um orçamento. [${campanha}/${secao}]`;
  a.href = 'https://wa.me/5567999999999?text=' + encodeURIComponent(texto);
});

O cliente recebe: "Olá! Vim pelo site e quero um orçamento. [reforma-out/hero]". Ele não precisa de painel, não precisa aprender GA4, não precisa perguntar nada — a informação chega junto com o contato, no lugar onde ele já trabalha.

Duas ressalvas honestas. O código entre colchetes é visível para quem está mandando, então mantenha discreto e sem nada constrangedor — [reforma-out/hero] tudo bem, [lead-frio-barato] não. E isso não é preciso ao ponto de virar prova: a pessoa pode apagar o texto antes de enviar. É indicativo, e indicativo já é infinitamente mais do que nada.
