Back-end

Tudo que não cabe no navegador: guardar dados, enviar e-mail, esconder uma chave de API, deixar o cliente editar o próprio conteúdo.

PARTE 1

Quando você precisa de servidor

O caminho entre “HTML puro” e “montar um back-end inteiro”. É aqui que moram os pedidos de cliente que hoje você precisa recusar ou improvisar.

Serverless functions

Novo

Em vez de manter um servidor ligado, você escreve uma função isolada que roda só quando alguém chama, e depois desliga. Sem servidor para administrar, sem custo fixo, e o plano gratuito da Vercel ou Netlify cobre muito mais do que uma landing page precisa.

Na Vercel, basta criar uma pasta api/ ao lado do seu HTML. Cada arquivo ali vira um endereço.

api/contato.js
export default async function handler(req, res) {
  if (req.method !== 'POST') {
    return res.status(405).json({ erro: 'Método não permitido' });
  }

  const { nome, email, mensagem } = req.body;

  if (!nome || !email) {
    return res.status(400).json({ erro: 'Nome e e-mail são obrigatórios' });
  }

  // a chave fica AQUI, no servidor — nunca no HTML
  const chave = process.env.CHAVE_EMAIL;

  // ... envia o e-mail ...

  res.status(200).json({ ok: true });
}

O arquivo acima responde em /api/contato. Do lado do site, você chama com fetch — aquilo da Parte 5.

Por que isso resolve o seu problema principal: a chave de API fica em variável de ambiente, no servidor, invisível para o visitante. É exatamente o que falta numa landing page estática e o motivo de tantas integrações serem impossíveis sem back-end.

Formulário que envia e-mail de verdade

Novo

O pedido mais comum depois do WhatsApp. Existem três caminhos, do mais simples ao mais controlado.

CaminhoComo funcionaCusto / esforço
Serviço de formulário
(Formspree, Web3Forms)		Você aponta o action do form para eles; o e-mail chega na caixa do clienteMinutos. Plano gratuito costuma bastar
Serverless + API de e-mail
(Resend, SendGrid)		Sua função recebe e dispara o e-mailUma tarde. Controle total do texto e do fluxo
Back-end próprioServidor rodando o tempo todoSó se houver outros motivos
o caminho mais rápido
<form action="https://formspree.io/f/SEU_ID" method="POST">
  <label for="email">Seu e-mail</label>
  <input id="email" type="email" name="email" required>

  <label for="msg">Mensagem</label>
  <textarea id="msg" name="mensagem" required></textarea>

  <button type="submit">Enviar</button>
</form>

Sem JavaScript nenhum, e continua funcionando com JS desligado. É difícil bater essa relação esforço/resultado.

Spam é garantido. Todo formulário público recebe robô. Os serviços acima já filtram, mas some um campo escondido (“honeypot”) que humano nunca preenche: se vier preenchido, é robô. Evita a maior parte sem incomodar ninguém com captcha.

Automação sem código

Novo

Ferramentas que conectam serviços por interface visual. Resolvem boa parte dos pedidos de “back-end” sem você programar — e são vendáveis como serviço à parte.

FerramentaCaracterística
Make (ex-Integromat)Visual, poderoso, plano gratuito generoso
ZapierO mais conhecido; mais caro
n8nCódigo aberto, pode rodar no seu próprio servidor

Um fluxo típico que o cliente valoriza: o formulário do site chega no Make; ele grava a linha numa planilha do Google, manda um e-mail de confirmação para quem preencheu, avisa o cliente no WhatsApp e cria o contato no CRM. Nada disso exige uma linha de código.

Oportunidade comercial: a automação normalmente vale mais para o cliente que a página em si — ela economiza o tempo dele toda semana, não uma vez. E é trabalho recorrente, diferente da landing page, que se entrega e acaba.

Headless CMS

Novo

Um painel onde o cliente edita o conteúdo, sem mexer no site. “Headless” significa que ele só guarda e entrega os dados — quem desenha a página continua sendo você.

OpçãoQuando faz sentido
Google SheetsO cliente já sabe usar. Publique a planilha e leia o JSON. Solução mais subestimada que existe
NotionSe o cliente já usa Notion, a API dele serve de CMS
Sanity, Strapi, ContentfulCMS de verdade, com tipos de conteúdo e permissões
Decap CMSGrava direto no repositório Git. Gratuito, sem banco de dados
Antes de montar qualquer CMS, faça a pergunta: com que frequência esse conteúdo muda de verdade? Cardápio que muda toda semana justifica. “Sobre nós” que mudou duas vezes em três anos não justifica — ali, editar o HTML e republicar custa menos para todo mundo.
